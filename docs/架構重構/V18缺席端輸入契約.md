# V18 缺席端輸入契約：source_location 與決策層否決

狀態：**定稿**（由草案定稿，監督裁決已納入；base develop 7699491）。實作：`feature/decision-v18-absent-input`。
需求出處：UEP_新架構技術設計提案 §9.3、§10.3、V18（缺席的 Discord 不錄音不參與）、INV-02；Bernie 11/10 的定義（見 §1）。
範圍：欄位契約＋propose 之前的否決＋shadow 紀錄。不含 SystemNotice、留言／到場請求、§9.3 到場仲裁、回條與移轉（週期 3）。

## 1. 定義（Bernie 11/10）

- Presence=NONE 表示她在主機中；此時沒有任何輸入輸出。睡覺是行程（Presence ACTIVE 且 Behavior=SLEEP），不是 NONE。
- 是否開 turn **只看位置**。輸入來源不是她目前所在的平台，或她在主機時的任何輸入，都屬於**缺席端輸入**，不開 turn、不經 Output Gate 放行。
- `source_location` 只描述「這句輸入從哪個場域進來」，**不代表她在場**；能不能互動仍由 Presence（Lease）決定。
- 每個平台都有可做監控的介面，但這不代表 UEP 本人在那裡（見 §7）。

## 2. 欄位

`UtteranceFact`（`uep/turn/models.py`）：

| 欄位 | 型別 | 說明 |
|---|---|---|
| `source_location` | `PresenceLocation \| None = None` | 輸入實際來源場域；閉集 desktop／discord／website。None = 來源未宣告（缺失） |
| `source_endpoint_id` | `str \| None = None` | 選填，對應 §10.2 endpoint 粒度；目前只記錄、不比對；也是 `actor_authenticated` 的必要條件之一（§5） |

不放 `SessionContext`（session 級，一個 session 內每句來源可能不同）；不放 `TurnCandidate`（否決發生在建 candidate 之前，proposer 不該看到）。

不可信任 `speaker_ref` 前綴與 `session.platform` 當來源：前者是呼叫端自填的說話者身分字串，後者是 session 級宣告（且經別名表映射），兩者都沒有簽發者。

`_sanitize` 遇到無效 `source_location`（不在 `PresenceLocation`）：計 `intake.invalid_source_location`，標記為 `invalid`，**視為不一致**（否決），不當成缺失。合法字串（如 `"desktop"`）會轉為 `PresenceLocation`。

## 3. 簽入點（誰填）

原則：**Host 不得在 `submit_utterance` 統一蓋上自己的 location**，否則 `discord:111` 進 desktop Host 會被蓋成 desktop 而放行。

| 位置 | 簽入責任 |
|---|---|
| `EchoPipelineHost._intake_stage_utterance`（`uep/echo/host.py`） | 讀輸入 stage 宣告的 `source_location`／`source_endpoint_id`（`getattr(stage, ..., None)`）；stage 沒宣告 = 缺失（計數）。不使用 Host 自身 location |
| Console `_submit`（`uep/console/commands.py`） | 工具層預設填 Host location；`over` 可傳 `source_location` 重現反例 |
| `_decide_interjection` | 由已通過閘門的 buffer 衍生的合成 fact，豁免 |
| 測試中直接建 `UtteranceFact` | 不帶欄位 = 缺失，維持現狀相容 |

### 外部 adapter 的簽入（P4，本次不實作）

- 在 Core 側 ingress 簽，不由 adapter 自報：ingress 以通過 HMAC 驗證的 `endpoint_id` 查「endpoint_id -> PresenceLocation」註冊表，產生 `source_location`／`source_endpoint_id`，並覆蓋 wire 上任何同名欄位。
- wire 協定不得從 client payload 反序列化 `source_location`；欄位只存在於行程內 dataclass。
- 註冊表由組裝層建立，adapter 不可自行註冊 location。

## 4. 否決規則

位置：`TurnOrchestrator.on_utterance`，`_sanitize` 之後、`input.utterance_final` 發布、`_listener_yield` 與 `aggregator.feed` 之前（`_absent_input_reason`）。缺席端文字因此不進 proposer（含 ListenerAware）、不進 aggregator buffer，**連含原文 blob 的 `input.utterance_final` 都不寫**。

比對對象為 **Host 持有的 location**（`host_location`），不用 `PresenceManager.peek`（docstring 禁止作授權判斷依據）。判定順序：

1. Host 不持有 Lease（她在主機或在其他平台）-> `presence_inactive`。沿用既有 reason_code：語意相同（Presence 非 ACTIVE），`_decide_turn` 對插話／tick 路徑仍用同一個字串，下游統計不需分兩種。優先於來源比對。
2. `source_location` 缺失 -> 現狀放行，計 `intake.source_location_missing`；`require_source_location` 開啟時 -> `source_location_missing`。
3. `source_location` != Host location（含 `invalid`）-> `absent_platform_input`。

全域停止與 audience 否決仍在 `_decide_turn`（`_vetoed`），不變。以上 reason_code 都是正常類（`turn.skipped`，非錯誤事件）。

Lease 快取落後（被撤銷尚未感知）由 Output Gate 二次接納擋（REJECT_STALE），不是本否決的責任。

## 5. Shadow 紀錄

否決並丟棄之前先寫一筆 `turn.skipped`（既有事件通道，不新增 migration；`reason_code` 本就是自由字串，只在事件 registry 的 `turn.skipped` payload 白名單擴充鍵）。**不保存原文**，只存 ref 與長度。

| 欄位 | 說明 |
|---|---|
| `reason_code` | `presence_inactive`／`absent_platform_input`／`source_location_missing` |
| `reply_mode` | 固定 `pass` |
| `utterance_ref`／`proposal_ref` | `es:<run_id>:<session_ref>:<seq>`（沒有 utterance 事件，故以冪等鍵樣式為 ref） |
| `source_location` | 來源場域；缺失為 `missing`，無效為 `invalid` |
| `source_endpoint_id` | 有才寫 |
| `speaker_ref`／`actor_id` | 說話者平台字串；actor 取身分映射結果，無映射用 `ctx.profile_actor_id`，再無則 `uep:unverified_speaker` |
| `is_owner` | 字串 `"true"`／`"false"`／`"unknown"`。身分映射（`IdentityDirectory.resolve_platform`）命中 owner 為 true、查不到為 false；沒有身分映射無法判定為 unknown（不猜）。注意：這是「記憶 owner」映射，不是「是否為 Bernie」的特判 |
| `len` | 文字長度 |
| `presence_request` | `bool \| None`：是否為到場／移轉請求。由 `presence.absent_intent` 判斷（True／False），無法判斷或失敗為 None（未判斷）；hook 見下 |
| `actor_authenticated` | `bool`：actor 是否為平台認證過的 ID。只看認證 ID，不比對顯示名稱；身分映射命中**且**帶有 ingress 簽發的 `source_endpoint_id` 才為 True，其餘（資訊不足）為 False。ingress 簽發落地前恆為 False |

時間用事件信封的時間戳。

`presence_request` 辨識 hook（後備路徑用；房內裁決：缺席端輸入不在各平台辨識，monitor 面原樣轉發到核心，由核心決策點判斷到場／移轉請求，兩條路徑共用 `presence.absent_intent` 的中性入口 `judge_absent_intent`）：`TurnOrchestrator(presence_request_hook=...)`，預設 `uep.turn.orchestrator.no_presence_request`（回 None）。介面為 `(UtteranceFact) -> bool | None`。**意圖由核心決策點判斷，可用決策模型（Laya 路線）；授權只來自已認證 actor 與規則**，模型輸出不能產生或提升授權（提案 §18.3）。預設 hook（`presence_request_hook=None`）改走決策點 `presence.absent_intent`（`uep/decision/presence_absent_intent.py`，sync、一律 shadow，模型到位前用 `rules.absent_intent`）：`presence_request` -> True、`message` -> False、`other`（無法判斷）-> None；決策點逾時／busy／例外／輸出無效一律 None，不影響否決。傳入自訂 callable 則完全取代預設，`uep.turn.orchestrator.no_presence_request` 可用來明確關閉判斷。判斷時不開 turn、不載入人格輸出，原文只在記憶體（`native`），不進 decision_log 與事件 payload。本次不實作仲裁、回條或移轉。

## 6. fail-closed 開關與 P4 前置

- 組態 `UEP_REQUIRE_SOURCE_LOCATION`（布林，預設 false；`uep/config.py` `require_source_location`）。組裝層讀取後注入 Host（`set_require_source_location`），Host 不自己讀設定。
- 開啟後缺失即否決（`source_location_missing`）；不一致照舊。
- 守門：`uep.assembly.check_source_location_policy(input_locations, require)`，`assemble_core(input_locations=...)` 開頭呼叫。`input_locations` 含 desktop 以外的值且開關未開 -> `AssemblyError`，訊息寫明要開 `UEP_REQUIRE_SOURCE_LOCATION`。目前 repo 沒有外部 adapter 註冊點，預設 `("desktop",)` 不觸發；P4 的 adapter 註冊點出現時必須把場域傳進來。
- **P4 前置條件**：非 desktop adapter 接上 Core 之前必須開 fail-closed：(1) 輸入經 Core ingress 簽發 source_location（§3），不得自報；(2) 開關開啟（assembly 強制）；(3) P4 合併時把預設改為 true，並先讓輸入 stage 宣告 `source_location`；缺失計數在觀察期內應為 0。

## 7. 監控 vs Presence

平台端點的能力分兩類：

1. **監控**：只讀她的狀態，任何平台都可以有。
2. **presence-bound 的互動與輸出**：只有 Presence ACTIVE 在該平台時才成立。

監控端點不等於她在場。缺席端受限輸入通道的**主入口**是監控面的 `AbsentInboundItem`（工具層 E 切片；草案，待裁決），它不是 `UtteranceFact`，沒有 `speaker_ref -> turn` 路徑，也不構成 `source_location` 或 Presence 的依據。經監控端點入站的輸入一律是缺席端輸入，即使 Presence 正 ACTIVE 於同一平台。

本契約的 orchestrator 否決（§4）是**縱深防禦的後備關卡**：任何 `UtteranceFact`，只要來源不等於 Presence.location，或 Presence 不在 ACTIVE（Host 無 Lease），都會被否決並寫 §5 的 shadow 紀錄。到場／移轉請求的意圖兩條路徑都由核心決策點 `presence.absent_intent` 判斷（可用決策模型，不由平台端辨識；`AbsentInboundItem` 經 `absent_intent_input_from_item` 只轉換欄位，monitor 通道接線屬工具層 E5）；授權只來自已認證 actor 與規則，模型輸出不能產生或提升授權。兩條路徑（主入口 `AbsentInboundItem` 與此後備關卡）的 shadow 紀錄欄位同形，欄位名稱以 §5 為準（特別是 `actor_authenticated`）。本次不實作仲裁、回條或移轉。

監控介面可顯示的內容遵守 INV-07 與 audience：狀態可以顯示，私人內容不得經由公開平台的監控介面外洩。這只寫進契約，不寫程式。

端點註冊與 capability 的完整契約由工具層另開卡起草：「平台端點契約：監控能力 vs presence-bound 互動／輸出」（草案，待裁決；對應其 §4.4、§5 的 EC-2、M-2、M-3）；本文只涵蓋與 V18 相關的部分。

## 8. 與草案的差異

| 項目 | 草案 | 定稿 | 理由 |
|---|---|---|---|
| 否決位置 | A／B／C 待裁決 | B：`on_utterance` 的 `_sanitize` 後、發布與 feed 之前 | 監督裁決 |
| 否決時 `input.utterance_final` | 已有 event_id 可 `_skip` | 不發布（避免原文 blob 落地） | shadow 紀錄不得保存原文 |
| 比對對象 | 以 `source_check` callable 注入 | `host_location` 純值＋`require_source_location` 旗標 | 比 callable 簡單，不改 `veto(ctx)` 簽名 |
| Host 無 Lease | 在 `_vetoed` 的 `auth is None` | 提前到 `on_utterance`（含任何輸入） | 她在主機時任何輸入都是缺席端輸入，且需 shadow 紀錄 |
| 無效值 | 計 `intake.invalid_source_location` | 同，reason 用 `absent_platform_input` | 視為不一致 |
| `_decide_turn` 重複檢查 | 方案 C 才有 | 無 | 採 B，缺席端文字不進 buffer，無需復核 |
