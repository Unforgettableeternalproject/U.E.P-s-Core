## 一、模型載入機制

### 1.1 STT 模組（語音識別）

**使用技術棧**:
- ✅ **Transformers (Hugging Face)** - 主要框架
- ✅ **PyTorch** - 深度學習引擎
- ✅ **Whisper** - OpenAI 語音識別模型

**載入方式**:
```python
from transformers import AutoModelForSpeechSeq2Seq, AutoProcessor, pipeline

# 步驟 1: 載入模型
self.model = AutoModelForSpeechSeq2Seq.from_pretrained(
    model_path,  # 本地路徑或 HF model ID
    torch_dtype=torch.float16,  # GPU: float16, CPU: float32
    low_cpu_mem_usage=True,
    use_safetensors=True
)

# 步驟 2: 載入處理器
self.processor = AutoProcessor.from_pretrained(model_path)

# 步驟 3: 創建 Pipeline
self.pipe = pipeline(
    "automatic-speech-recognition",
    model=self.model,
    tokenizer=self.processor.tokenizer,
    feature_extractor=self.processor.feature_extractor,
    device=self.device  # "cuda:0" or "cpu"
)
```

**模型選擇邏輯**:
```python
if self.use_local_model and os.path.exists(self.whisper_local_path):
    model_path = self.whisper_local_path  # 優先使用本地
else:
    model_path = self.whisper_model_id    # 降級到 Hugging Face Hub
```

**當前配置** (已修改):
```yaml
whisper_model_id: "openai/whisper-base"  # HF model ID
whisper_local_path: "models/stt/whisper/whisper-base"  # 本地路徑
use_local_model: true
```

**硬編碼默認值** (程式碼中):
```python
# stt_module.py line 90-91
self.whisper_model_id = self.config.get("whisper_model_id", "openai/whisper-large-v3")
self.whisper_local_path = self.config.get("whisper_local_path", "models/stt/whisper/whisper-large-v3")
```

⚠️ **潛在問題**:
- 程式碼中的默認值仍指向 `whisper-large-v3`
- 如果配置檔讀取失敗，會降級到舊模型

## 二、核心系統架構

### 2.1 系統層級結構

```
核心層 (core/)
├── 系統控制
│   ├── controller.py          - UnifiedController (系統監督者)
│   ├── system_initializer.py  - SystemInitializer (啟動協調)
│   ├── framework.py           - CoreFramework (模組管理)
│   └── registry.py            - 模組註冊表與載入
│
├── 事件與通訊
│   ├── event_bus.py           - EventBus (發布-訂閱系統)
│   ├── router.py              - Router (事件路由)
│   └── module_coordinator.py  - ModuleCoordinator (模組協調)
│
├── 狀態與會話
│   ├── states/
│   │   ├── state_manager.py   - StateManager (狀態機)
│   │   ├── state_queue.py     - StateQueueManager (狀態佇列)
│   │   └── sleep_manager.py   - SleepManager (睡眠狀態)
│   └── sessions/
│       ├── session_manager.py     - UnifiedSessionManager
│       ├── general_session.py     - GeneralSessionManager (GS)
│       ├── chatting_session.py    - ChattingSessionManager (CS)
│       └── workflow_session.py    - WorkflowSessionManager (WS)
│
├── 工作上下文
│   ├── working_context.py     - WorkingContextManager (協作通道)
│   └── status_manager.py      - StatusManager (情緒與狀態)
│
├── 系統迴圈
│   ├── system_loop.py         - SystemLoop (主迴圈)
│   └── qt_system_loop.py      - QtSystemLoopManager (Qt 整合)
│
└── 前端橋接
    ├── frontend_bridge.py     - FrontendBridge (前端管理)
    └── reload_coordinator.py  - ReloadCoordinator (熱重載)
```

| **UnifiedSessionManager** | sessions/session_manager.py | 統一會話管理 | 核心必需 ✓ |
| **GeneralSessionManager** | sessions/general_session.py | GS 生命週期 | 核心必需 ✓ |
| **ChattingSessionManager** | sessions/chatting_session.py | CS 對話會話 | 可選 ? |

### 4.3 Echo Kernel 需求

**根據改進計畫，Echo Kernel 需要**:
1. **Shared Memory** (Story KB / Plan KB / Preferences)
   - 可能需要 MEM 模組的某些部分
   - 但不需要完整的 FAISS 向量檢索？
   
2. **Foreground/Background 雙迴圈**
   - 可能需要重構現有的 SystemLoop
   - 或建立全新的迴圈系統
   
3. **Task Engine** (Task Graph + 排程)
   - 可能與現有 WorkflowSession 衝突
   - 需要全新設計？
   
4. **Skill Registry & Permission Gate**
   - 與現有 Framework 的模組註冊不同
   - 需要新的權限系統

**評估**: Echo Kernel 可能需要「重新設計」而非「精簡現有系統」
